# Experiment Script

## Project Name

**Smart Classroom Attendance System**

---

# Purpose

This document provides the testing procedure for evaluating the Minimum Viable Product (MVP) of the Smart Classroom Attendance System. The experiment aims to observe how students and lecturers interact with the system and identify any usability issues before full development.

---

# Experiment Objective

To determine whether users can successfully log in, record attendance, and view attendance information using the Smart Classroom Attendance System without assistance.

---

# Target Participants

| Participant | Number |
|------------|--------|
| First-Year Students | 5 |
| Second-Year Students | 3 |
| Lecturer | 1 |
| Total Participants | 9 |

---

# Materials Required

- Laptop or desktop computer
- Internet connection
- Smart Classroom Attendance System prototype
- Student ID and Password for testing
- Observation sheet
- Feedback form

---

# Testing Scenario

Participants will imagine that they have arrived for class and need to record their attendance using the Smart Classroom Attendance System.

---

# Testing Tasks

## Task 1: Login

**Instructions**

1. Open the Smart Classroom Attendance System.
2. Enter your Student ID.
3. Enter your Password.
4. Click **Login**.

**Expected Result**

- User logs in successfully.
- Student Dashboard appears.

---

## Task 2: Record Attendance

**Instructions**

1. Click **Mark Attendance**.
2. Wait for the confirmation message.

**Expected Result**

- Attendance is successfully recorded.
- Confirmation message is displayed.

---

## Task 3: View Attendance History

**Instructions**

1. Open **Attendance History**.
2. Check today's attendance record.

**Expected Result**

- Attendance history is displayed correctly.

---

## Task 4: Logout

**Instructions**

1. Click **Logout**.

**Expected Result**

- User returns to the login page.

---

# Observation Checklist

| Observation | Yes | No |
|-------------|-----|----|
| User logged in successfully | ☐ | ☐ |
| User understood the interface | ☐ | ☐ |
| Attendance recorded successfully | ☐ | ☐ |
| User completed all tasks | ☐ | ☐ |
| User required assistance | ☐ | ☐ |

---

# Data to Record

For each participant, record:

- Login success or failure
- Time taken to log in
- Time taken to record attendance
- Number of errors encountered
- Assistance required
- User comments
- Satisfaction score

---

# Moderator Instructions

During testing:

- Do not guide participants unless necessary.
- Observe user actions carefully.
- Record any errors or confusion.
- Encourage participants to think aloud while completing tasks.
- Ask follow-up questions after testing.

---

# Post-Test Questions

1. Was the login process easy to complete?
2. Was recording attendance simple?
3. Did you encounter any problems?
4. Which part of the system was confusing?
5. What improvements would you suggest?
6. Would you use this system for your classes?

---

# Expected Outcome

The experiment is successful if participants can complete all tasks with minimal assistance, record attendance accurately, and report a positive user experience. The collected feedback will be used to improve the Smart Classroom Attendance System before the final prototype is developed.
