# 1. Introduction

The Smart Classroom Attendance System was developed as a semester-long project to solve problems associated with traditional classroom attendance management. Manual attendance recording is often time-consuming, prone to human error, and difficult to monitor efficiently. Our goal was to create a simple web-based prototype that allows students, lecturers, and administrators to manage attendance records more effectively using HTML, CSS, JavaScript, and Browser Local Storage.

Throughout the semester, our team gradually transformed an initial idea into a working Minimum Viable Product (MVP) by following the software development process taught in the ICT111 course.

---

# 2. Project Journey

Our project began with identifying a real problem experienced in educational environments. We conducted customer discovery, defined user requirements, created user stories, and identified the minimum features required for an MVP.

During the development process, we designed the user interface, created role-based dashboards, implemented Browser Local Storage for data persistence, and tested each feature through multiple development sprints.

As the project progressed, we continuously improved the prototype based on testing and documentation requirements. By the final lab, all major features had been integrated into one complete system with supporting documentation, screenshots, reports, and presentation materials.

# 4. What Worked Well

Several aspects of the project were completed successfully.

## User Authentication

Users can log in using their Student ID or staff account, and the system redirects each user to the correct dashboard.

## Attendance Submission

Students can submit attendance records through a simple attendance form.

## Local Storage

Attendance records and user information are stored using Browser Local Storage, allowing the prototype to function without a backend server.

## Attendance History

Students, lecturers, and administrators can view attendance records through dedicated interfaces.

## Search and Filtering

Attendance records can be searched and filtered, making information easier to locate.

## Dashboard Metrics

The prototype provides useful attendance summaries for administrators.

## Landing Page

A professional landing page introduces the project and connects visitors to the prototype.

# 5. Challenges Encountered

Although the project was successful, we experienced several challenges during development.

One challenge was connecting multiple HTML pages while maintaining consistent navigation and authentication.

Another challenge involved managing Browser Local Storage correctly to ensure attendance records remained available after refreshing the browser.

Preventing duplicate attendance submissions also required additional JavaScript validation.

Maintaining consistency between documentation and the actual prototype became increasingly important as more features were added throughout the semester.

Finally, coordinating team contributions within one GitHub repository required careful communication and planning.

---

# 6. How We Solved These Challenges

Our team solved these problems by dividing responsibilities according to each member's role.

We regularly tested every feature after implementation and corrected JavaScript errors immediately.

GitHub commits allowed us to monitor project progress and identify changes made by each team member.

We reviewed all documentation before the final submission to ensure consistency between the reports, screenshots, prototype, and repository structure.

---

# 9. Project Limitations

The current prototype has several limitations because it was developed as an academic MVP.

The system stores information only in Browser Local Storage, meaning data is available only on the device where it was entered.

The prototype does not include a backend server or cloud database.

Passwords are stored for demonstration purposes and are not encrypted.

The prototype is designed to demonstrate software concepts rather than provide production-level security or scalability.
