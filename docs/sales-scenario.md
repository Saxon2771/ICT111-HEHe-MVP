# Sales Scenario

## 1. Project Title

Smart Classroom Attendance System

## 2. Target User / Customer

- Primary users: University students and lecturers
- Secondary users: Academic administrators and course coordinators
- Decision-maker: Department head, academic administrator, or university IT coordinator
- Product name used in promotion: Attendify

## 3. Situation / Context

A lecturer begins a class with 40 students. The lecturer currently checks attendance using a paper sheet, verbal roll call, or a class group message. This process takes several minutes and may produce missing, duplicated, or inaccurate records. Students also have no simple way to check their attendance history, while lecturers must manually search old records when preparing reports.

The department wants a faster attendance process that can be demonstrated using normal web browsers without special equipment.

## 4. Pain Point

The current attendance process creates several problems:

- Class time is lost during manual attendance checking.
- Students may forget to sign the attendance sheet.
- Records may contain duplicate, missing, or incorrect entries.
- Students cannot easily view their own attendance history.
- Lecturers spend extra time searching and organizing records.
- Administrators do not have a clear attendance overview.
- Paper records are difficult to update and analyze.

## 5. Product Introduction

The project team introduces the Smart Classroom Attendance System during a short classroom and department demonstration. The lecturer opens the landing page, selects the demo, and logs in using a sample account. The system then demonstrates the student, lecturer, and administrator workflows.

The product is introduced as an academic web prototype that uses Student ID and Password authentication, Browser Local Storage, role-based dashboards, attendance recording, attendance history, search, filtering, status updates, and dashboard metrics.

## 6. Value Message

For university students, lecturers, and academic administrators who experience slow and inaccurate manual attendance processes, our Smart Classroom Attendance System helps them record, view, and manage attendance more efficiently by providing secure role-based login, automatic attendance storage, searchable records, and clear dashboards.

## 7. Sales Approach Using the 4 P's

### Product

The core product is faster and more accurate attendance management.

The actual product is a browser-based attendance system with:

- Student ID and Password login
- Student, lecturer, and administrator roles
- Attendance submission
- Attendance history
- Search and filtering
- Status updates
- Dashboard metrics

The augmented product includes:

- Demo instructions
- Sample login accounts
- Basic user support
- Training during the classroom demonstration
- Future report export and database integration

### Price

For the academic pilot, the prototype can be tested at no cost by one class or department. A future production version could use a department subscription or university license based on the number of courses and users.

The sales message emphasizes reduced administration time and improved record accuracy rather than the lowest possible price.

### Place

The prototype is distributed through:

- The project landing page
- A normal desktop or mobile web browser
- Class group chats
- University email
- Classroom presentations
- Department websites or learning platforms

### Promotion

The project will use:

- Direct classroom demonstration
- Lecturer and student referrals
- University email
- Class group chat messages
- Student club social media
- A clear Try Demo call-to-action

## 8. Sales Conversation / Pitch Moment

**Team:** How much class time is normally used to check attendance?

**Lecturer:** It may take five to ten minutes, especially in a large class.

**Team:** Our Smart Classroom Attendance System allows students to log in, submit attendance, and receive a saved record. Lecturers can review, search, filter, and update attendance from a dashboard.

**Lecturer:** Can students check their own attendance?

**Team:** Yes. Students can view their attendance history after logging in. The system also prevents duplicate attendance for the same student, course, and date.

**Administrator:** How is the information stored?

**Team:** The current academic prototype stores demonstration data in Browser Local Storage. It does not require a server for the classroom demo. A production version would use secure authentication and a central cloud database.

**Lecturer:** What should we do next?

**Team:** Please test the student and lecturer workflows, complete the user-testing tasks, and provide feedback. We will use the results to complete the final improvements before Lab 14.

## 9. Expected User Action

After hearing the pitch or watching the demonstration, the user should:

1. Open the landing page.
2. Click the demo or login button.
3. Log in using a sample account.
4. Test the attendance workflow.
5. Review attendance records and dashboards.
6. Provide usability feedback.
7. Recommend whether the department should continue with a larger pilot.
